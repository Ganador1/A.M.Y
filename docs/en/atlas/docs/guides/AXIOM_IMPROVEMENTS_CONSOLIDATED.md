<a id="1-visión-sintetizada"></a>
## 1. Synthesized Vision
AXIOM META 4 is heading to be the "Scientific Operating System" capable of executing the complete discovery cycle: ideation → planning → experimentation (simulated and physical) → multi-domain analysis → rigorous validation → reproducible publication → self-improved feedback. The strategic objective is to achieve Level 4 Autonomy (decides WHAT to research, HOW and WHEN, with minimal human intervention) while maintaining traceability, ethics, and rigor.

<a id="7-riesgos-y-mitigaciones"></a>
## 7. Risks and Mitigations
| Risk | Impact | Mitigation |
|--------|---------|------------|
| Monolith growth | Complexity and debt | Decoupled facades and services + clear contracts |
| LLM latency and cost | Inefficient scaling | token_cost metrics + intermediate result caching |
| Knowledge fragmentation | Loss of synergies | Central KG + standard query API |
| Lack of sandbox | Unsafe execution risk | Mandatory SandboxExecutor for dynamic code |
| Heavy dependencies | High time-to-env | Modularization of requirements + installation profiles |
| Superficial validation | Low trust | Multi-agent peer review + reproducibility metrics |
| Lack of prioritization | Resource consumption without ROI | Strategic Planner with gap scoring |

<a id="9-detalle-técnicos-clave-por-componente-sprint-1"></a>
## 9. Key Technical Detail by Component (Sprint 1)
<a id="advanced_scientific_database_servicepy"></a>
### advanced_scientific_database_service.py
Functions: CRUD (Hypothesis, Evidence, Refinement, ModelEntry), list/paginate, search_text (LIKE), search_semantic (vector store stub), upsert embeddings.
Interfaces: Uses existing SQLAlchemy models; adds Pydantic DTOs. Internal repository pattern.

<a id="vectorstoreprovider"></a>
### VectorStoreProvider
Interface: add_text(id, text, metadata), similarity_search(query, k) -> list[(id, score, metadata)].
Implementations: InMemory (cosine over tf-idf or fictitious embeddings). Future hook FAISS/Chroma.

<a id="plausibilityscoringservice"></a>
### PlausibilityScoringService
Inputs: hypothesis_text, metadata.
Initial heuristics: duplication penalty (distance < threshold), extreme length penalty, bonus for detected scientific entities (domain regex). Returns dict of metrics + composite.

<a id="experimentscheduler"></a>
### ExperimentScheduler
Table: experiments(id, name, payload_json, status, retries, max_retries, depends_on, created_at, updated_at, started_at, finished_at, error_text).
API: enqueue, fetch_next, mark_running, mark_failed, mark_succeeded, requeue_failed.

<a id="sandboxexecutor"></a>
### SandboxExecutor
Execution in subprocess.run([...], timeout=sec). Limit stdout/err size, sanitize. Returns status + truncated logs + code hash.

<a id="config-yaml"></a>
### Config YAML
`config/agents.yaml`: roles, models, parameters (temperature, max_tokens).
`config/models.yaml`: provider, base name, limit parameters, enabled.
Loader with hot cache.

<a id="normalización-respuestas"></a>
### Response Normalization
Create schemas: HypothesisRead, EvidenceRead, PublicationRead unifying fields and adding `integrity_hash` when applicable.
