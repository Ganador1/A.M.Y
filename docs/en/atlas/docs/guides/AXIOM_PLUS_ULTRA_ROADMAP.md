<a id="6-validación-cruzada-diseño-inicial"></a>
## 6. Cross-Validation (Initial Design)
Pipeline:
1. Domain detection (taxonomy + NLP on title/description/variables).
2. Validation tasks per domain (evidence score, risks, physical/chemical/biological plausibility).
3. Matrix C[i,j] = compatibility / conflict / neutral.
4. Global Score = Σ(w_d * domain_score_d) + λ(positive_compatibilities - pen*conflicts) - risk_penalty.
5. Hard rules (biosecurity, legal) invalidate hypotheses.
6. Automatic refinement loop if high conflict.

<a id="12-riesgos-y-mitigaciones"></a>
## 12. Risks and Mitigations
| Risk | Impact | Mitigation |
|--------|---------|-----------|
| High GPU load | Slowness / long queues | Asynchronous adapters + queues + structure caching + priority scheduler |
| Data complexity | Inconsistency | Versioned schema + JSON schema validations + adapter contracts |
| Bio/ethical risks | Compliance | Ethics agent + hard rules + sensitive domain whitelist + periodic auditing |
| Changing SOTA dependencies | Obsolescence | Adapter abstraction and fallback + plugin regression tests |
| Training cost | Budget | Prefer lightweight fine-tuning (LoRA) and RAG |
| Hashing fragmentation (blockchain vs provenance) | Confusion / duplication | Unify hashing pipeline and register mapping in publication manifest |
| Non-integration of UQ in decisions | False certainties | Incorporate uncertainty metrics into global score and publication gating |
| Contention in distributed pools | Deadlocks / inefficiency | Latency metric supervision + timeouts + watchdog over processes |
| Ontological drift | Obsolete validations | Scheduled re-indexing + re-evaluation triggers |
| Metric overload | Performance degradation | Sampling and aggregation (rollups) + historized compression |
